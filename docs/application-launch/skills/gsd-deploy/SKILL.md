# gsd-deploy — 部署编排

> 从 PR 合并到生产稳定运行之间的部署环节。gsd 的 `/gsd-ship` 止步于创建 PR；本 skill 接管"合并后"的部署编排。

## 何时使用

- PR 合并到主干后，准备部署到某环境
- 需要设计灰度/蓝绿/滚动发布策略
- 部署前需要跑一遍检查清单
- 部署后需要验证服务是否真正起来
- 部署失败需要回滚

## 部署前检查清单（BLOCK 级，全部通过才允许部署）

### 代码与构建
- [ ] 主干分支 CI 全绿（lint / 类型检查 / 单元测试 / 集成测试）
- [ ] 构建产物已生成且版本号正确（语义化版本）
- [ ] 构建产物已推送到制品库（registry / artifact store）
- [ ] lockfile 已提交，依赖版本锁定

### 数据库
- [ ] 所有迁移脚本已合入主干（不在部署时临时跑迁移）
- [ ] 迁移脚本已在前置环境验证过
- [ ] 大表变更已分步进行（见 gsd-migration skill）
- [ ] 回滚迁移脚本已准备并验证

### 配置
- [ ] 目标环境的环境变量已就绪（密钥已轮换或同步）
- [ ] 配置中心（如有）已更新
- [ ] 特性开关已设置到预期状态
- [ ] 目标环境与开发/测试环境配置差异已核对

### 依赖服务
- [ ] 下游依赖服务版本兼容（API 契约未破坏）
- [ ] 外部服务（支付、短信、第三方 API）可用性已确认
- [ ] 缓存预热方案已准备（如需要）

### 回滚准备
- [ ] 回滚方案已明确（回滚到哪个版本、如何回滚）
- [ ] 回滚后数据库兼容性已评估（迁移是否需要同步回滚）
- [ ] 回滚演练已在前置环境做过（或确认可快速执行）

## 部署策略选择

根据变更类型和风险选择策略：

| 场景 | 推荐策略 | 理由 |
|------|---------|------|
| 常规迭代，变更可控 | 滚动发布 | 简单、资源占用低 |
| 大版本变更，风险较高 | 蓝绿部署 | 秒级切换、秒级回滚 |
| 需要按流量比例验证 | 金丝雀发布 | 逐步放量、风险可控 |
| 数据库 schema 变更 | 先扩后缩（见 gsd-migration） | 避免停机 |

### 金丝雀发布观察窗口

| 流量比例 | 观察时长 | 关注指标 |
|---------|---------|---------|
| 1% | 30 分钟 | 错误率、延迟、告警 |
| 10% | 1 小时 | 错误率、延迟、业务指标 |
| 50% | 2 小时 | 全量指标 + 用户反馈 |
| 100% | 持续观察 | 确认稳定，关闭灰度 |

任一比例出现错误率飙升或核心指标异常，**立即回滚**，不要等观察窗口结束。

## 部署后验证（必做）

部署完成 ≠ 部署成功。必须验证：

### 健康检查
- [ ] 健康检查端点返回 200（见 gsd-healthcheck skill）
- [ ] 就绪探针通过，流量已切入新版本
- [ ] 实例数符合预期，无 CrashLoopBackOff

### 业务验证
- [ ] 核心业务流程冒烟测试通过（登录、下单、支付等关键路径）
- [ ] 新功能按预期工作
- [ ] 监控仪表盘无异常告警

### 日志验证
- [ ] 新版本日志正常输出，无大量 ERROR
- [ ] 链路追踪能看到新版本请求（见 gsd-observability skill）
- [ ] 无预期外的 WARNING

## 回滚决策树

```
部署后发现问题
    │
    ├─ 影响核心功能（无法下单/支付/登录）？
    │     ├─ 是 → 立即回滚，不等排查
    │     └─ 否 → 进入观察
    │
    ├─ 错误率 > 5%？
    │     ├─ 是 → 5 分钟内未定位 → 回滚
    │     └─ 否 → 继续
    │
    └─ 延迟 P99 翻倍且持续？
          ├─ 是 → 10 分钟内未恢复 → 回滚
          └─ 否 → 观察 30 分钟，稳定则保留
```

**回滚原则**：先恢复服务，再排查根因。回滚不是失败，是标准应急动作。

## 回滚后必做

- [ ] 通知相关方（业务、客服、值班群）
- [ ] 记录回滚原因和时间点
- [ ] 保留现场日志和监控截图
- [ ] 24 小时内开复盘（见 gsd-incident skill）
- [ ] 修复问题后重新走部署流程，不要直接热修

## 产出文档

每次部署应留下部署记录（可放在 `.planning/` 或运维 wiki）：

```markdown
# 部署记录：<版本号> @ <时间>

## 变更内容
- 关联 PR / Commit
- 变更摘要

## 部署策略
<策略 + 流量比例 + 观察时长>

## 验证结果
- 健康检查：✅/❌
- 冒烟测试：✅/❌
- 监控指标：✅/❌

## 异常与处理
<如有>

## 回滚情况
<如回滚：原因、时间、恢复时长>
```

## 与 gsd 工作流的衔接

- `/gsd-ship` 创建并合并 PR → 触发本 skill
- 本 skill 完成部署 → 触发 `gsd-healthcheck` 验证
- 部署出问题 → 触发 `gsd-incident` 应急
- 部署涉及数据库 → 先走 `gsd-migration`
